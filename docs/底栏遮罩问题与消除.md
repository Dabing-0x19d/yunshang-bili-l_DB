# 底栏遮罩（HdsTabs gradientMask）：它是什么、怎么来的、怎么消除的

> 2026-09-24 · 涉及 `entry/src/main/ets/pages/Index.ets`（底部 Tab 栏的 `barFloatingStyle`）
> 一句话结论：这条"灰带"是 **HdsTabs 浮动底栏自带的遮罩**（`gradientMask`），不是消息页引入的 bug；
> 已按用户要求 **全局置为 `Color.Transparent`（不再绘制）**。

---

## 1. 它是什么

`Index` 的底部 Tab 栏用 HdsTabs 的浮动 bar，其中一项就是这层遮罩：

```ts
.barFloatingStyle({
  barWidth: { smallWidth: 264, mediumWidth: 264, largeWidth: 264 },
  barSideMargin: 20,
  barBottomMargin: 27 + this.navIndicatorHeight,
  gradientMask: { maskColor: Color.Transparent, maskHeight: 92 },   // ← 现状（已关掉）
  ...
})
```

SDK 定义（`sdk/default/hms/ets/api/@hms.hds.hdsBaseComponent.d.ets`）原文：

| 字段 | 文档原文 | 说明 |
|---|---|---|
| `HdsTabsFloatingStyle.gradientMask` | "Sets gradient mask for **bottom of tabs**" | Tabs 底部的遮罩带 |
| `HdsTabsBackgroundStyle.maskColor` | "Sets the color of the **tab bar mask**" | 遮罩颜色 |
| `HdsTabsBackgroundStyle.maskHeight` | 不填时 =「组件高度（含底部 TabBar 高）+ 32vp」 | 本工程显式给了 92 |

**最关键的一条性质：它绘制在内容层之下。**
证据：首页截图的底部内容清晰、没有被灰蒙住 → 遮罩若在内容之上，内容必然被压暗。

---

## 2. 原来是怎么配的（"遮罩怎么来的"）

本会话起点时的写法：

```ts
gradientMask: { maskColor: this.isDarkMode ? '#662C2C2C' : '#66F1F3F5', maskHeight: 92 },
```

全工程检索 `gradientMask` 共 8 处，**只有 Index 这一处用了真实颜色**；其余 7 处（`SearchPage` / `WatchHistoryPage` / `DynamicsPage` 的 UP 面板 / `HdsMiniBarButton` / `HdsMaterialPill` / `WhisperInputBar`）都写死 `Color.Transparent`，它们旁边的注释都是"省略会渲染成黑色遮罩"。

也就是说：Index 这条"真实渐变"是当初特意配的（给悬浮底栏和内容之间做渐隐过渡），也因此成了**唯一会显形**的一处。它不是被谁新加进来的 —— 一直存在，只是以前没有"内容没铺满底部、又显示着底栏"的页面，所以没露过脸。

---

## 3. 为什么只有"消息页/我的页"看得见

因为遮罩在内容层之下，**底部有没有不透明内容**就决定了它是否露出：

| 页面 | 屏幕底部区域 | 现象 |
|---|---|---|
| 首页 / 动态 | 卡片列表铺满到底 | 遮罩被内容盖住 → 看不见 |
| 我的页 | 内容 `bottom: 96` 留白，透出壁纸 | **遮罩露出 → 一条灰带** |
| 消息页（开关关闭、底栏可见时） | 列表末尾留白 + 壁纸 | **同样露出**（与我的页逐像素一致） |
| 消息页（开关打开 / 横屏，底栏隐藏） | — | 底栏不渲染 ⇒ 遮罩也不渲染 |

真机像素（深色主题，屏幕 1320×2120，取底栏下方一行、中间区平均）：

| 状态 | 均值 RGB |
|---|---|
| 消息页 · 底栏可见（改动前） | (38, 38, 41) |
| 消息页 · 底栏可见（改动后） | (30, 29, 35) |
| 消息页 · 底栏隐藏（无遮罩基准） | (24, 24, 27) |

差值说明两件事：① 这层带子确实**随底栏显隐**（±14）；② 关掉遮罩后仍比纯壁纸亮 ~6 —— 那是**玻璃底栏自身的柔光/投影**，不属于 `gradientMask`，无法靠 maskColor 去掉。

## 4. 怎么定位的（可复现手法）

```bash
HDC="path/to/your/sdk/default/openharmony/toolchains/hdc.exe"

# 截图（⚠️ 必须 MSYS_NO_PATHCONV=1，否则 /data/... 会被 Git Bash 转成 Windows 路径）
MSYS_NO_PATHCONV=1 "$HDC" shell snapshot_display -f /data/local/tmp/shot.jpeg
# 拉回（⚠️ 本地路径给【相对路径】，绝对路径会被拼成 cwd+路径 而失败）
MSYS_NO_PATHCONV=1 "$HDC" file recv /data/local/tmp/shot.jpeg shot.jpeg

# 看几何（List / ListItem / TabBar 的 bounds）
MSYS_NO_PATHCONV=1 "$HDC" shell uitest dumpLayout -p /data/local/tmp/layout.json
MSYS_NO_PATHCONV=1 "$HDC" file recv /data/local/tmp/layout.json layout.json
```

结论靠两样东西交叉验证：
1. **PIL 逐行像素**（对比"底栏可见 / 底栏隐藏 / 不同页面"同区域的 RGB），确认这层随底栏显隐；
2. **dumpLayout 几何**，确认底栏与内容的位置关系（本次还反推出本机 **1vp ≈ 2.55px**：`barWidth` 264vp = 674px；`barBottomMargin` 27vp = 69px）。

⚠️ 教训：一开始"消息列表被遮挡"被误判成遮罩的锅，实际那是**避让留白**（见第 6 节）。**取证先分清"是装饰层"还是"布局留白"**。

---

## 5. 怎么消除的（本次改动）

分两步走，最终落在一步：

1. 先按要求**只关消息页**：新增 `getBottomBarMaskColor()`，`activeTab === 2` 时返回 `Color.Transparent`，其余页面保持原值。
2. 随后用户要求**其他页面也消除** → 直接改成全局透明，并删掉了那个方法：

```ts
// Index.ets 的 barFloatingStyle 内
gradientMask: { maskColor: Color.Transparent, maskHeight: 92 },
```

至此**全工程的 `gradientMask` 口径统一为 `Color.Transparent`**。

构建：`bash _bld.sh _bld_maskall.log` → `BUILD SUCCESSFUL` / `EXITCODE=0`（此改动只影响渲染，无逻辑变更）。

---

## 6. 回退方式

| 想回到 | 怎么改 |
|---|---|
| 恢复原来的渐变（所有页面） | 把 `Color.Transparent` 换回 `this.isDarkMode ? '#662C2C2C' : '#66F1F3F5'` |
| 只关消息页、其它页面保留渐变 | 换回上一版写法：新增 `getBottomBarMaskColor()`，`activeTab === 2` 返回 `Color.Transparent`，否则返回上面那串三元 |

副作用提醒：关掉遮罩后，**首页/动态滚动时内容滑到底栏后面不再有渐隐过渡**（边缘会略"硬"）。如果想保留过渡又不要灰带，可考虑把 `maskColor` 换成与页面背景同色的低透明度值，而不是直接透明。

## 7. 同一批改动（相邻事项，便于一起查阅）

- `WhisperPage` 的底栏避让留白：从 `List.padding({bottom})`（静态内缩，观感像列表被截断）改为 **List 末尾的空白 ListItem**（跟随信息流滑动），高度 `max(0, listBottomPadding() - cardListMargin)`。
- `WhisperPage` 新增**滚动联动底栏显隐**（与首页/动态同款：delta > 10vp 收起 / 反向展开 / 回顶 5vp 内复位），守卫 `msgTabAutoHide || isLandscape` 直接 return。
- 「消息页 Tab 自动隐藏」开关（我的 → 功能开关，默认关闭，`preferences: my_app_settings / msgTabAutoHide`）。
