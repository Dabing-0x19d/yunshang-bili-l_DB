# 弹幕「显示不全 / 隐藏过早 / 开关异常」诊断报告

范围：`DanmakuView.ets` / `DanmakuController.ets` / `DanmakuRenderer.ets` / `DanmakuTrackManager.ets` / `DanmakuGrpcParser.ets` / `DanmakuService.ets` / `DanmakuFilter.ets` / `VideoPlayerPage.ets`（集成侧）

## 结论速览

| 症状 | 根因置信度 | 一句话根因 |
|---|---|---|
| 开关弹幕异常 | ★★★ 实锤 | 开关 = **卸载/重挂整个 DanmakuView** → 每次开启都新建 controller 并**重新下载全部分段**，几秒空窗 + 重复流量；关灯/全屏切换同样换实例 |

## 症状一：显示不全

### 1.1 ★★ 轨道间距与实际字号脱钩（压叠）
- `DanmakuTrackManager.initialize()`：`trackHeight = this.config.fontSize`（默认 **25**，全工程**没有任何 UI 会修改它**）；
- 但数据侧两条解析路径都把字号放大 1.5 倍：
  - `DanmakuGrpcParser.parseDanmakuElem()`：`fontSize: Math.round(fontsize * 1.5)` → 标准 25 → **37**，中 36 → **54**，大 45 → **68**；
  - `DanmakuService.parseXmlDanmaku()`：同样 `rawFontSize * 1.5`。
- 渲染时 `item.fontSize || config.fontSize` → **item.fontSize(37+) 恒定生效**，`config.fontSize` 只剩"轨道间距"这一个作用。
- 后果：相邻轨道间距 25px，字高 37~68px → **压叠 12~43px**；`displayArea` 调小（轨道更多更密）时更严重；大字号弹幕（54/68）会横跨 2~3 条轨道压住别人的弹幕。
- `item.height = trackHeight(25)` 同样低报，顶/底静止弹幕的 y 计算也随之偏小。

### 1.2 ★★ 横屏/全屏 canvas 与视频区错位（AGENTS.md 已记录的既有问题，未修）
- `ovDanmakuCW()/ovDanmakuCH()`（VideoPlayerPage L362-371）传入的是"视频宽度"，但 `DanmakuView` 内部 `Canvas` 是 `.width('100%').height('100%')`，实际元素尺寸由所在 Stack 决定；
- AGENTS.md 实测：某横屏分支 canvas **831×517vp**，视频 XComponent 只有 **~691vp 宽、左缘偏 70vp** → 弹幕坐标系与视频区不重合：右侧约 1/6 的滚动时间画在视频外（评论面板上），左侧起步段不在视频上。
- 「竖屏横看」分支两者完全重合（实测 [20,20][1440,818]）——所以该问题**只在部分布局出现**，容易漏测。

### 1.3 ★ maxCount=100 截断保留的是"最旧"的弹幕
- `updateVisibleDanmaku()`：候选按时间桶升序收集 → 过滤/分配后仍按时间升序 → `slice(0, maxCount)` 砍掉的是**队尾（最新）弹幕**；
- 注释写"此时列表里只剩真正还在屏幕上的弹幕，截断影响可忽略"——不成立：热门视频密集时段同屏候选轻松超 100，**新弹幕被系统性挤掉**，与轨道"放不下就丢"叠加放大。

### 1.4 次要（少显示，不重叠）
- 轨道碰撞"放不下就丢"（`assignScrollTrack` 返回 -1 → `dropped`）——对齐 B 站的设计行为，本身正确；
- `estimateTextWidth` 偏保守：emoji 按 1.2em、变体选择符 U+FE0F（零宽）与半角假名（>255）都按全角计 → 碰撞判定偏紧 → 密集时段更早判"放不下"；
- 数据侧：gRPC `progress <= 0` 的弹幕直接丢（t=0 处的弹幕）；`weight`/`density` 字段加载了但从未参与优先级。

## 症状二：隐藏过早

### 2.1 ★★ 出屏判定全用估算宽度，从不 measureText
- 分配时 `item.width = estimateTextWidth(...)`（`DanmakuTrackManager.assignTrack`）；
- 渲染器 `isInViewport()`：`x >= -item.width` → 低于即置 `visible=false`；
- 控制器候选过滤：`item.x + item.width < 0 → 剔除`。
- 三处用的是**同一个估算值**，与真实绘制宽度无关。只有居中静止弹幕走了 `measureText`（`applyCenteredX`），滚动弹幕终生不测。
- **估算 < 实宽** 时（ASCII 宽字母 w/m/W/M/@/%、未来若开加粗、某些字体的数字/标点），弹幕尾巴还在屏幕内就被判定出屏 → **滚到一半整条消失**；估宽偏大则只是晚消失（无害）。
- 这同时解释"隐藏过早"和部分"显示不全"（可见部分提前没了）。

### 2.2 ★ 候选窗口 trailWindow 不看 item.duration（当前默认不触发，属埋雷）
- `trailWindow = min(30s, max(11s, 8000/config.speed + 3s))`；
- 非固定速度下每条 duration 恰好 = 8000/speed，窗口多 3s 余量 ✓；
- 但 `scrollFixedVelocity = true` 时 `speed = canvasWidth/8000*speedMul`，长弹幕 `duration = (W+w)/(W/8000·mul) > trailWindow` → **长弹幕滚到一半被候选窗口剔除**（画面上直接消失）。默认 false，一旦打开该设置即复现。

### 2.3 ★ seek 误判阈值 5s
- `updateTime()`：`|time - prev| > 5000` 即 `resetScrollingState()`（全场弹幕作废重进）。
- 卡顿、系统瞬时挂起、解码停顿都可能让 timeUpdate 间隔 >5s → 弹幕"突然全部消失又重新进来"，观感即"隐藏过早"。

### 2.4 设计值（非 bug，列出供确认是否符合预期）
- 顶/底静止弹幕固定 5s（`assignTopTrack/assignBottomTrack` 的 default 5000），淡入淡出各 200ms；
- 滚动弹幕穿越时长 8s/speedMul。

## 症状三：开关弹幕时有问题（本报告最实锤的一条）

### 3.1 ★★★ 开关 = 卸载/重挂整个 DanmakuView
- 三处挂载点全部是条件渲染：`VideoPlayerPage` L7465、L8073、L8853 → `if (this.isDanmakuEnabled && ...)`；
- **关**：整个组件销毁（`aboutToDisappear` 只 stopRendering）。"保留 controller 供复用"的注释已失效——`@Reusable` 早已移除，controller 随实例一起被丢弃；
- **开**：新实例 → 新 controller → Canvas onReady → `autoInitialize()` → `await controller.initialize()` → **重新网络下载分段**（实测 1.7 万条约 4 秒）→ 期间 `onTimeChange` 因 `initialized=false` 被跳过 → **开关后几秒内一条弹幕没有**，且同样的分段重复下载；
- 快速连开连关：每次都是新实例，`isLoading` 锁跨实例无效 → 并发多个 initialize 竞态。
- 另注意：**`danmakuConfig.enable` 从未被写过**（全工程只有 `DanmakuConfigPanel` 那个未使用的面板会写它），渲染器里 `if (!this.config.enable) return` 形同虚设——开关实际是靠"挂不挂组件"实现的。

### 3.2 ★★★ 关灯 / 进出全屏同样触发"重开一次"
- 三个互斥分支（视频上 / 关灯视频外 / 关灯右侧）各挂一个 `DanmakuView` 实例；
- 切换关灯模式、进出全屏 → 组件销毁重建 → **重新下载分段 + 空窗**；
- 专门建的统一 Builder `buildDanmakuView()`（L7426）**没有用在这几处**，三处仍是手写重复参数。

### 3.3 ★★ config 对象被整体替换后，控制器持有旧引用
- 控制器在 `aboutToAppear` 用当时的 `this.config` 构造，之后**从未有人调用 `controller.updateConfig()`**（全工程无调用点）；
- 但页面有两处 `this.danmakuConfig = new DanmakuConfig()` 整体替换：L2251（启动同步，早于挂载，安全）与 **L1801（`refreshDanmakuApiSource()` 异步校正，晚于挂载，竞态）**；
- 替换后 `@Link` 会把新对象同步给 DanmakuView，但 controller/renderer/filter/trackManager 仍持旧对象 → 之后对新对象字段的任何修改都不生效；
- 当前实际影响：**apiSource 异步校正若晚于 DanmakuView 挂载，控制器仍用旧数据源加载**（grpc/xml 与设置不一致）；将来若加"透明度/速度/字号"设置项，会全部静默失效。
- `DanmakuView` 对 `config` 没有 `@Watch`，替换发生时无任何感知。

## 验证方法（hilog 抓什么，一次实机可全部确认）

1. **开关重下载实锤**：`[DanmakuView] aboutToAppear开始` / `[DanmakuController] initialize被调用` / `gRPC分段 N 加载成功，共 X 条` —— 关一次再开一次弹幕，这三组日志应**成对重复出现**；
2. **轨道压叠实锤**：`[TrackManager] 初始化轨道: 正向N条` → N = floor(画布高×0.85/25)；对照截图里实际字高（应明显大于 25vp）；
3. **canvas 错位实锤**：`[DanmakuController] 画布尺寸: WxH` 与 `uitest dumpLayout` 里 XComponent bounds 对照（横屏分支应能复现 831 vs 691）；
4. **中途消失实锤**：找一条纯英文/宽字母长弹幕（如含 WWW、@、%），看它是否在滚到左边缘之前消失；
5. **密集时段饥饿**：`stats.displayedCount` 是否长时间顶在 100。

## 修复方向（按性价比排序，未动手）

1. **开关与关灯/全屏切换常驻化**：DanmakuView 改为跨分支常驻（几何随状态驱动，与 XComponent 同套路），显隐用 `config.enable` + `Visibility.Hidden`；`enable=false` 时 renderer 主动 `clear()`。一次解决"重新下载 + 空窗 + 快速开关竞态"。
2. **config 引用修正**：页面上对 `danmakuConfig` **只改字段、不换对象**（apiSource 校正改为 `this.danmakuConfig.apiSource = saved`）；或在 DanmakuView 加 `@Watch('config')` → `controller.updateConfig(...)`。
3. **轨道高度与字号解耦**：`trackHeight = max(config.fontSize, 本轨道实际字号) + 行距`；或干脆 `trackHeight = item 实际字号 + 4`，顶/底同理。
4. **滚动弹幕真实宽度**：分配轨道时用一次 `measureText`（结果缓存到 item，`measuredWidth` 字段已有，扩展到滚动弹幕），替换估算值——顺带把碰撞检测和出屏判定一起修准。
5. **maxCount 截断改向**：优先保留已上屏（track>=0）的弹幕，新弹幕按时间新者优先参与轨道竞争；或直接调大 maxCount 并依赖轨道丢弃控制密度。
6. **trailWindow 用 per-item 上界**：`now > item.time + max(trailWindow, item.duration + 1000)` 再剔除。
7. （顺手）`estimateTextWidth` 把 U+FE0F/零宽字符记 0 宽；gRPC `progress <= 0` 放行 t=0。

### 关键决策与坑

- **`Visibility.Hidden` 而不是 `None`**：`None` 不参与布局 → Canvas 量不到尺寸 → `onCanvasReady` 走进“尺寸无效”分支，`canvasReady` 永远为 false，**弹幕永不初始化**。常驻化后若改用 `None` 会直接踩这个坑。
- **归一化必须基于 `rawFontSize`**：若拿 `fontSize` 当输入，每次分配都会在上一次结果上再乘一次比例（字号累积放大）。
- **`measureWidth` 返回 0 表示“没有渲染上下文”**，调用方 / 轨道管理退回估算值，保证 Canvas 未就绪时仍能工作。
- **1.5 倍放大从两个解析器搬到 `stdFontSize`**：标准弹幕的实际显示尺寸与修复前一致（37），中 / 大号从 54 / 68 收敛到约 43 —— 这是消除压叠的必要代价，视觉上仍能区分大小号。
- 轨道数会变少（同样画布高度下约为原来的一半）：**10 条互相压叠 → 5 条清晰轨道**，可读性更好但同屏上限下降。若觉得太稀疏，把 `DANMAKU_SIZE_MAX_RATIO` 调到 1.0（所有弹幕同号）或调小 `TRACK_GAP`。

### 未修（需先确认再动）

- **横屏 / 全屏 canvas 与视频区错位**（1.2 节）：需按布局分支重新推导画布几何，改动面较大；
- **关灯 / 进出全屏仍在三个互斥分支间换实例**（3.2 节）：彻底方案是像 XComponent 那样做成单一常驻实例、几何随状态驱动，风险较高，本轮未做。
